# 01. 제품 개요

> 최종 수정일: 2026-11-24

## 목적

신입사원이 실무에 투입되기 전에 **회사에서 쓰는 언어/프레임워크로, 실무와 비슷한 화면과 업무 흐름**을 미리 만들어 보게 합니다. 과제를 매번 사람이 만들지 않아도 되도록 Claude API가 과제를 생성합니다.

## 사용자

| 사용자 | 하는 일 |
|---|---|
| 교육 담당자(사수) | 과제를 생성하고, 제안을 넘기거나 채택하고, 제출물을 채점표로 리뷰 |
| 신입사원 | 명세서와 예시 화면을 보고 구현, 채점표로 스스로 점검 |

1차 버전에서는 두 사용자가 같은 화면을 씁니다. 로그인·권한 구분은 백로그입니다.

## 핵심 흐름

1. 언어/프레임워크와 난이도를 고르고 **[과제 및 예시 화면 생성]**
2. 과제 아이디어 하나가 제안됨 → **채택** 또는 **넘기고 다른 아이디어**
3. 채택한 과제를 신입사원에게 전달
4. 신입사원이 구현 후 제출 → 사수가 채점표로 리뷰

화면별 세부 동작은 [02_ui-spec](02_ui-spec.md), 과제 내용의 규칙은 [05_assignment-rules](05_assignment-rules.md)를 봅니다.

## 결과물 (과제 1개에 포함되는 것)

- **상세 개발 명세서**: 개요, 필수 컨트롤·기술, 코드 구조, 필수 요구사항, 선택 기능, 예외 처리, (중급) 데이터 설계 가이드
- **구현 목표 예시 화면**: 선택한 프레임워크의 실제 컨트롤 구조가 보이는 UI 목업
- **채점표**: 필수 100점 + 가산점

정확한 데이터 형식은 [04_assignment-schema](04_assignment-schema.md)에 있습니다.

## 지원 범위 (MVP)

- 언어/프레임워크 5종 — [06_frameworks](06_frameworks.md)
- 난이도 2단계(초급·중급) — [05_assignment-rules](05_assignment-rules.md#난이도-정의)
- 화면 유형 12종 — [07_layouts](07_layouts.md)
- 제안 기록, 채택, 브라우저 저장, Markdown 내보내기

## 백로그 (이후 버전)

우선순위는 파일럿 피드백 후 정합니다.

- 제출 코드를 Claude가 채점표 기준으로 1차 리뷰
- 과제 묶음(커리큘럼): 채택 과제를 주차별로 묶어 배정
- 유지보수형 과제: 기존 코드의 버그 찾기, 필드 추가하기
- 과제 중간 요구사항 변경 이벤트
- 넘기는 이유 선택("너무 쉬움", "다른 업무 분야")을 다음 제안에 반영
- "이 화면 유형은 제외" 옵션
- 초급과 중급 사이 단계(가벼운 CRUD)
- 로그인·역할 구분, 서버 DB 저장

## 용어

| 용어 | 뜻 |
|---|---|
| 과제 | 명세서 + 예시 화면 + 채점표 한 세트 |
| 아이디어 | 아직 채택되지 않은 과제 제안 |
| 화면 유형 | 과제 화면의 레이아웃 패턴 (예: 칸반 보드) — [07](07_layouts.md) |
| 스킨 | 예시 화면을 WPF·WinForms 등 프레임워크 모양으로 그리는 방식 |
| 필수 기능 | 통과 기준에 들어가는 기능 |
| 선택 기능 | 편의 기능, 가산점만 있음 |
| 채택 / 넘김 | 제안된 아이디어를 쓰기로 함 / 다른 아이디어를 요청함 |
