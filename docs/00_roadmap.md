# 00. 개발 로드맵

> 최종 수정일: 2026-11-25
> 현재 위치: **4단계 완료** (2026-11-25) → 다음은 5단계(Claude API 연동)

진행 순서의 핵심은 **"데이터 형식 → 가짜 데이터로 화면 완성 → 진짜 API 연결"**입니다. 화면과 렌더러를 Mock 데이터로 먼저 끝내 두면, Claude API를 붙일 때는 "같은 형식의 JSON을 만들어 내는지"만 신경 쓰면 됩니다. API 비용도 아낄 수 있습니다.

| 단계 | 이름 | 예상 기간 | 의존 |
|---|---|---|---|
| 0 | 기획·목업 확정 | 완료 | — |
| 1 | 프로젝트 골격 | 1일 | 0 |
| 2 | 데이터 형식과 샘플 데이터 | 1~2일 | 1 |
| 3 | 화면 셸 (Mock 모드) | 3~4일 | 2 |
| 4 | 예시 화면 렌더러 | 4~5일 | 2 |
| 5 | Claude API 연동 | 3~4일 | 3, 4 |
| 6 | 저장·내보내기 | 2일 | 5 |
| 7 | 생성 품질 점검·튜닝 | 2~3일 | 5 |
| 8 | 사내 배포·파일럿 | 1주 | 6, 7 |

3단계와 4단계는 서로 독립적이라 두 명이면 동시에 진행할 수 있습니다.

---

## 1단계. 프로젝트 골격

**작업**
- [03_architecture](03_architecture.md#폴더-구조)의 폴더 구조대로 모노레포 생성 (`apps/web`, `apps/server`, `packages/shared`)
- 웹: Vite + React + Tailwind CSS, ESLint/Prettier
- 서버: Node.js + Express, `.env` 로딩, `GET /api/health`
- Git 저장소, `.gitignore`(`.env` 포함), 브랜치 규칙

**완료 기준**
- `npm run dev` 한 번으로 웹과 서버가 함께 뜬다
- 웹에서 `/api/health` 호출 결과가 화면에 보인다

## 2단계. 데이터 형식과 샘플 데이터

**작업**
- [04_assignment-schema](04_assignment-schema.md)를 `packages/shared/src/schema`에 zod 스키마로 옮김 (Draft, Assignment)
- [05](05_assignment-rules.md)·[06](06_frameworks.md)·[07](07_layouts.md)을 `packages/shared/src/catalog` 상수로 옮김
- 조립기 `composeAssignment(draft, framework)` 구현 (`packages/shared/src/compose`)
- 목업 HTML 안의 샘플 과제 16개를 `fixtures/*.json`(Draft 형식)으로 옮김

**완료 기준**
- fixture 16개 × 프레임워크 5종 = 80개 조합이 Draft·Assignment 검증을 모두 통과한다
- 채점표 필수 합계 100점 검증이 테스트로 돌아간다

## 3단계. 화면 셸 (Mock 모드)

**작업** — [02_ui-spec](02_ui-spec.md) 기준
- 상단 컨트롤 바, 로딩 오버레이
- 결정 바(채택/넘김), 제안 기록
- 명세서 패널(개요, 컨트롤·기술, 코드 구조, 요구사항, 선택 기능, 힌트, 예외, 설계 가이드, 채점표)
- 서버의 Mock 모드(`USE_MOCK=true`)가 fixture를 돌려주게 연결

**완료 기준**
- API 키 없이 목업과 똑같이 동작한다 (생성 → 넘김 → 채택 → 기록 다시 보기)

## 4단계. 예시 화면 렌더러

**작업** — [07_layouts](07_layouts.md) 기준
- 공통 컨트롤 컴포넌트(TextBox, ComboBox, Grid, Tabs 등)를 스킨 5종으로 구현
- 화면 유형 12종 레이아웃 구현, 컨트롤 이름 주석 핀
- 목업 HTML의 그리기 코드를 컴포넌트 단위로 옮기면 빠릅니다

**완료 기준**
- 16개 fixture × 프레임워크 5종 = 80개 조합이 오류 없이 그려진다 (렌더 테스트)

## 5단계. Claude API 연동

**작업** — [08_prompt](08_prompt.md) 기준
- `POST /api/assignments` 구현, 프롬프트 조립, 구조화 출력, 스키마 검증, 1회 재시도
- 최근 제안 아이디어를 넘겨 중복·같은 화면 유형 연속 방지

**완료 기준**
- 프레임워크 5종 × 난이도 2종으로 각 3회 생성 시 검증 실패율 5% 미만
- 생성 시간 30초 이내

## 6단계. 저장·내보내기

**작업**
- 제안 기록·채택 과제를 브라우저 저장소(localStorage)에 보관
- 채택 과제를 Markdown 파일로 내보내기 (신입에게 전달용)

**완료 기준**
- 새로고침해도 기록이 남는다, 내보낸 파일만으로 과제를 이해할 수 있다

## 7단계. 생성 품질 점검·튜닝

**작업**
- [08_prompt의 품질 점검표](08_prompt.md#생성-품질-점검표)로 30개 이상 생성물 검토
- 반복되는 문제를 프롬프트·검증 규칙에 반영하고 [09_decisions](09_decisions.md)에 기록

**완료 기준**
- 사수 2명이 무작위 10개를 보고 "바로 신입에게 줄 수 있다" 8개 이상

## 8단계. 사내 배포·파일럿

**작업**
- 사내 서버 배포, API 키는 서버 환경 변수로만 관리
- 신입 1~2명에게 [05의 권장 일정](05_assignment-rules.md#권장-일정)대로 실제 과제 부여
- 피드백을 받아 [01의 백로그](01_product.md#백로그-이후-버전) 우선순위 조정

**완료 기준**
- 파일럿 참가자가 과제를 기간 안에 끝내고, 채점표로 리뷰를 마쳤다
