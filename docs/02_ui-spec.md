# 02. 화면 명세

> 최종 수정일: 2026-11-25
> 기준 목업: [`mockup/onboarding-mockup.html`](../mockup/onboarding-mockup.html)

이 문서는 **화면 영역과 동작**만 다룹니다. 화면에 표시되는 과제 내용(배점, 기술 목록 등)은 [05](05_assignment-rules.md)·[06](06_frameworks.md)·[07](07_layouts.md)이 기준입니다.

## 전체 배치

```
┌ 헤더 ─────────────────────────────────────────┐
├ 상단 컨트롤 바 (스크롤해도 상단 고정) ─────────┤
├ 결정 바 + 제안 기록 ───────────────────────────┤
├ 명세서 패널 (5) │ 예시 화면 뷰어 (7) ─────────┤
└ 안내 문구 ─────────────────────────────────────┘
```
- 너비 1024px 이상: 좌우 5:7 분할, 예시 화면 뷰어는 스크롤해도 따라옴
- 그보다 좁으면 세로로 쌓되 **예시 화면 → 명세서** 순서

## 1. 헤더

- 제품 이름, "프로토타입" 표시(개발 중에만)
- 채택한 과제가 있으면 "채택한 과제 N개"

## 2. 상단 컨트롤 바

| 요소 | 동작 |
|---|---|
| 언어/프레임워크 드롭다운 | 목록은 [06](06_frameworks.md) |
| 난이도 토글 | 초급(기초 UI) / 중급(실무 CRUD) |
| [과제 및 예시 화면 생성] | 현재 선택으로 새 아이디어 요청, 생성 중엔 비활성화 |
| 변경 안내 문구 | 선택이 현재 보고 있는 과제와 다르면 "생성 버튼을 누르면 새 아이디어를 제안해요" 표시 |

## 3. 로딩 오버레이

- 생성 중 본문 위를 덮고 진행 단계를 표시
- 새 생성: 선택 조건 분석 → 화면 유형과 업무 정하기 → 명세서 작성 → 예시 화면 그리기
- 넘김: 다른 화면 유형 찾기 → 업무 정하기 → 명세서 작성 → 예시 화면 그리기
- 실제 API 응답이 오면 즉시 닫음 (단계 표시는 연출)
- 실패 시 오류 메시지와 [다시 시도] 버튼

## 4. 결정 바

표시 내용: 아이디어 번호, 프레임워크·난이도, 상태 배지, 과제 제목, 화면 유형, 요청 부서 예시

### 제안 상태 흐름

| 현재 상태 | 버튼 | 결과 |
|---|---|---|
| 검토 중 | [넘기고 다른 아이디어] | 현재 → 넘김, 새 아이디어 추가(검토 중) |
| 검토 중 | [이 과제로 채택] | 현재 → 채택 |
| 넘김 | [다시 검토해 채택] | 현재 → 채택 |
| 넘김 | [다른 아이디어 보기] | 새 아이디어 추가 |
| 채택 | [채택 취소] | 현재 → 검토 중 |
| 채택 | [다른 아이디어도 보기] | 새 아이디어 추가, 채택 유지 |

- 새로 생성할 때 이전 항목이 "검토 중"이면 자동으로 "넘김"
- 채택은 여러 개 가능
- 다음 아이디어를 고르는 규칙은 [05의 제안 규칙](05_assignment-rules.md#아이디어-제안-규칙)

### 제안 기록

- 2개 이상이면 결정 바 아래에 가로 스크롤 칩 목록
- 칩: 번호, 제목, 프레임워크·난이도, 상태
- 칩을 누르면 그 과제로 이동하고 컨트롤 바 선택도 그 값으로 바뀜

## 5. 명세서 패널

위에서부터 이 순서로 표시합니다. 각 항목의 데이터는 [04](04_assignment-schema.md)의 필드명으로 적었습니다.

1. 프레임워크·난이도 배지, 제목, 시나리오
2. 화면 유형 / 예상 소요 / 산출물 (3칸), 학습 목표
3. 필수 사용 컨트롤, 핵심 기술 (배지)
4. 코드 구조 (`architecture`): 계층 상자를 화살표로 연결, 계층별 파일, 규칙
5. 요구사항 카드 (`requirements`): "필수" 배지
6. 선택 기능 (`optionalFeatures`): 점선 상자, "가산점" 배지, "하지 않아도 감점 없음"
7. 구현 힌트 (초급만)
8. 예외 처리 조건 (`exceptions`)
9. 데이터·API 설계 가이드 (`dataGuide`, 중급만): 질문 목록 + 제출물
10. 채점표 (`rubric`)
    - 항목을 누르면 체크되고 점수가 즉시 합산
    - 필수 점수 "N / 100", 가산점은 "+N"으로 따로 표시
    - 등급 기준은 [05](05_assignment-rules.md#채점표)
    - [체크 모두 해제]

## 6. 예시 화면 뷰어

- 상단: 제목, 플랫폼·화면 유형, [컨트롤 이름] 토글, [원본 크기]/[화면에 맞춤]
- 본문: 모눈 배경 위에 예시 화면
- [컨트롤 이름] 켜짐: 영역마다 번호 핀과 점선, 아래에 번호별 컨트롤 이름·설명 범례
  - 현재 화면에 없는 컨트롤은 범례에서도 뺌
- [원본 크기]: 가로 스크롤로 실제 크기 보기 (모바일용)
- 클릭해서 바뀌는 부분: 목록 행·카드·예약 블록 선택, 탭 전환, 마법사 단계 이동 — 세부는 [07](07_layouts.md)
- 선택 기능 영역은 주황색 "선택" 배지로 표시

## 7. 내보내기

- **채택**한 과제의 결정 바에 [명세서 내보내기 (.md)], [예시 화면 내보내기 (.svg)] 버튼
- 파일 이름: `과제제목_프레임워크_난이도` (파일 이름에 쓸 수 없는 문자는 `_`)
- 명세서(.md): 개요 → 예시 화면(같은 폴더의 .svg를 이미지로 연결) + 번호별 컨트롤 이름 → 컨트롤·기술 → 코드 구조 → 요구사항 → 선택 기능 → 힌트(초급) → 예외 → 데이터 설계 가이드(중급) → 채점표·등급
  - .svg 없이 .md만 받아도 과제를 이해할 수 있게, 컨트롤 이름은 글로도 넣음
- 예시 화면(.svg): 컨트롤 이름 핀을 켠 상태, 화면 유형의 처음 선택 상태로 그림

## 8. 기록 저장

- 제안 기록·채택 상태·보던 위치·컨트롤 바 선택을 이 브라우저에 저장 ([03](03_architecture.md#저장))
- 다시 열면 저장된 기록을 이어서 보여 주고, 기록이 없을 때만 첫 아이디어를 자동 생성
- 제안 기록 제목 옆 [기록 비우기]: 확인 후 모두 지우고 새 아이디어를 생성

## 접근성·공통

- 모든 버튼 높이 44px 이상, 키보드 포커스 표시
- 입력 글자 16px 이상(모바일 확대 방지)
- 움직임 줄이기 설정이면 애니메이션 끔
